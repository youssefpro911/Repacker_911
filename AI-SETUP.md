# RPK AI — Jan local model setup

RPK uses **Jan Desktop** to run your chosen local model. RPK connects to Jan's OpenAI-compatible Local API Server on your own computer. You do not need Ollama or a separate llama.cpp command-line executable.

## 1. Start a model in Jan

1. Open Jan Desktop and download or import a GGUF model supported by Jan.
2. Load the model and make sure it is ready for a chat.
3. Open **Settings → Local API Server**.
4. Start the Local API Server. Jan's default address is:

`http://127.0.0.1:1337/v1`

Jan exposes a model list at `/models` and chat completions at `/chat/completions`. The API key is optional depending on your Jan settings.

Jan documentation: https://docs.jan.ai/desktop/api-server

## 2. Connect RPK to Jan

1. Run `rpk_ai.exe` from the RPK Windows package, or press **AI Assistant — Jan** in RPK Builder.
2. Keep the default Server URL unless you changed Jan's port or API prefix.
3. Enter the API key only if Jan requires one.
4. Click **Refresh models**, then select the model Jan reports.
5. The connection and model selection are saved under `%LOCALAPPDATA%\RPK\ai.ini`.

The RPK Jan connector accepts loopback addresses only (`127.0.0.1`, `localhost`, or `::1`) and uses Windows HTTP APIs. It does not send requests to a cloud service.

## 3. Optimize a folder before building

1. Select your source folder and archive output in RPK Builder.
2. Click **Optimize with Jan**.
3. RPK scans file counts, sizes, classifications, and sampled entropy.
4. RPK sends Jan aggregate statistics only. It does **not** send file contents or file names.
5. Jan returns a structured recommendation. RPK validates every setting against its supported limits before applying it to the controls.
6. Review the settings, then click **Build archive**.

## How the adaptive compression works

Jan recommends settings such as the LZMA preset, dictionary size, solid block size, worker count, and codec mode. The actual byte compression is performed by RPK's native lossless codecs, not generated by the language model.

With **Adaptive** codec mode, RPK tests each actual solid block as it is produced. It samples up to 256 KiB from the beginning, middle, and end of the block, tests LZMA2 and Zstandard, compares their encoded sizes with Store, and uses the winner to encode the complete original block. The activity log shows each decision while packing. Jan can recommend the global tuning settings; RPK's measured per-block trials make the codec choice on the real data. The final archive is still built and verified by the normal RPK core. A measured sample is a useful guide, not a guarantee that every possible setting has been tested.

The model does not rewrite source files, use lossy transforms, disable SHA-256 checks, or directly modify the archive format. Every extracted file remains subject to the normal integrity checks.

## Troubleshooting

- **No models listed:** Start or load a model in Jan, confirm the Local API Server is running, and press Refresh models again.
- **Connection refused:** Check that Jan's Local API Server is started and that the URL/port matches Jan's settings.
- **HTTP 401:** Check the optional API key.
- **HTTP 404:** Check that the API URL ends with the correct prefix, normally `/v1`, and refresh the model list.
- **Model is slow:** This is controlled by the model and inference settings in Jan, not by RPK's archive worker-thread setting.
